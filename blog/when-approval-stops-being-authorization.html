When Approval Stops Being Authorization

October 2026 · Krushna Dash

While working on software security automation at IBM, I spent time around an ML-assisted vulnerability pipeline built with watsonx and Granite, Mend, GitHub, and Jira. The visible task was remediation: process findings, track issues, and propose fixes. The harder problem was controlling what happened around the fix—deduplicating work, gating pull requests on review, making retries idempotent, and leaving an audit trail.

The question I kept returning to was what happens between approval and execution. A reviewer signs off on a patch. Then the repository advances, a dependency changes, the agent regenerates the diff, or the approval expires. The tool may still be capable of applying a patch. That does not mean the patch in front of it is still authorized.

Authorization can drift

Lapse is an experimental harness for measuring this gap. It tests whether coding agents and their surrounding tool policies preserve the actual scope of a user’s approval, rather than simply completing a repair. In the model I am testing, authorization binds together a task, a specific diff, a target repository revision, an allowed file scope, and a live grant. If one of those facts changes, execution requires a new decision.

This is easy to lose in an agent pipeline. Approval is often treated as a Boolean attached to a task: approved once, permitted later. But the thing a reviewer inspected may no longer be the thing an agent executes. A changed patch hash is not a clerical detail. Neither is a new base commit or an expired grant. They change the object of authorization.

Paired interventions

The evaluation uses controlled pairs of synthetic remediation episodes. Each episode begins with a fictional maintenance task, a patch proposal, and a simulated review decision. In one world, the approval remains valid. In the paired world, the harness changes exactly one fact before execution: revocation, TTL expiration under a virtual clock, a changed patch hash, a new repository base state, expanded file scope, or a duplicate retry.

Keeping the rest of the task fixed makes the failure legible. If behavior changes, I can connect it to the authorization intervention rather than to a different prompt or repair. This is the same reason I rely on basin-level error analysis in my spatiotemporal ML work at UT Austin’s Center for Space Research: aggregate performance can hide the narrower failure that actually matters.

A deterministic policy oracle tracks task, state, capability, action, and permission as separate objects. The runner records what the agent attempted, what the simulated tool executed, whether a valid repair completed, whether the system requested reapproval, and whether a retry produced duplicate effects. An agent requesting an unauthorized edit that the tool blocks is not the same failure as a repository being modified. A system that refuses every edit is not correct either; it has respected the boundary by abandoning the task.

Binding approval to change

The local methods prototype is written in Python and includes typed event schemas, fixture validation, a deterministic episode runner, pytest coverage, and a CLI for emitting JSONL traces, summary statistics, and figures. The experimental program compares several enforcement models: capability-only execution, approval checked once at proposal time, rules checked again at execution time, and grants cryptographically or structurally bound to exact patch hashes and repository versions. Version-pinned model-agent runs are the next empirical stage.

Lapse draws from the broader authorization questions explored by AuthorizationBench and the Agent Action Boundary Benchmark. Its focus is narrower: multi-stage software remediation, where time and repository state sit between a human decision and an agent action.

The distinction I care about is simple. A tool tells us what an agent can do. An approval should tell us exactly what it may do, to which state, and for how long. Lapse is an attempt to make the distance between those statements measurable.
